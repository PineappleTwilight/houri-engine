這是每個可調參數的說明：它控制什麼、值域多少、推到兩端會怎樣。

reader app 把這些放在翻譯設定頁，按階段分組。常用的預設顯示，其餘收在 **顯示進階選項** 開關後面。sandbox app 開放同一組旋鈕，方便在真機上測。

數值用輸入框填，會夾回這裡列的值域（超界拉回最近的界，不是拒絕）。效能下拉只列到你裝置的核心數為止。

## 翻譯

### 啟用翻譯
開關，預設關。章節下載完就翻。偵測、OCR、去字在裝置上跑；翻譯呼叫 LLM，所以跑的當下要連網。

### API key
你的 LLM 金鑰（自備金鑰），每個服務商各存一格，切換服務商不會弄丟。加密存在 Android Keystore，不內建。

### 目標語言
LLM 翻成的語言。預設台灣繁體中文。預設帶一組日翻中的 few-shot 範例；換成別的目標語言時範例會拿掉，免得把輸出帶往中文。

### 來源語言
丟進 prompt 的提示。實際來源由 OCR 模型決定，所以這只是個標籤。留自動偵測即可，除非 OCR 輸出被標錯語言。

### 服務商／模型／API base
服務商是預設選單：manga-image-translator 的 LLM 那組（OpenAI、DeepSeek、Gemini、Groq、Qwen、Sakura、自訂）外加 OpenRouter，全部 OpenAI 相容。預設 DeepSeek。模型可手填，或按 **抓取模型** 從服務商撈即時清單；留空＝用該服務商的預設模型。API base 只在自架／自訂（Sakura、自訂）才出現，其餘用內建端點。完整清單與撈取機制見 [PROVIDERS.md](PROVIDERS_zh.md)。

## 去字

### 去字方法
下拉，預設 **AI 去字**。兩個模式，對話框都一律平塗乾淨。差別只在壓在畫面上的字怎麼抹：

- **快速去字（BoxFill）** — 全部平塗，就近取周圍的顏色補。最快（一頁約半秒），但粗糙：畫面上的字會變成一塊平色塊，所以只在幾乎全是乾淨白泡的頁好看。
- **AI 去字（AOT-GAN）** — 泡泡平塗，再跑一次整頁 AOT-GAN 重建壓在畫面上的字底下的圖。高品質，預設。

為什麼泡泡一律平塗：把乾淨白泡送進去字模型純粹是壞處（會有淡淡黃暈，又花時間），所以只重建壓在畫面上的字。

### 去字外擴（bboxPad）
預設 16，單位像素。值域 0–64。去字範圍比偵測到的文字框外擴多少，用來涵蓋貼著邊緣的注音假名跟筆畫。

調小（往 0）：貼框邊的假名被漏掉、留殘留。調大（往 64）：去字伸進旁邊的畫面。

## 排版

### 排版方向
下拉，預設自動。自動跟著原文（CJK 走直排）。標題或字體讓偵測判錯時，可強制直排或橫排。

### 文字顏色（colorMode）
下拉，預設自動。自動依去字後的背景逐區挑黑字或白字（亮底黑字、暗底白字）。mono 一律黑字配白邊，比較單純，靠白邊在暗背景上維持可讀。

### 文字描邊（fontBorder）
開關，預設開。給譯文字加描邊。在雜亂或暗的背景上，描邊是維持可讀的關鍵；關掉就是純色字，可能融進畫面看不清。

### 字級上限（fontSizeMax）
預設 60，單位像素。值域 20–120。排版會用到的最大字級。調低：大泡泡裡的字顯小、撐不滿。調高：短句字級爆大、不自然。

### 字級下限（fontSizeMin）
預設 9，單位像素。值域 6–40。最小字級；再小寧可溢出框也不縮。調低（往 6）：塞得進但難讀。調高（往 20）：小泡泡塞不下、溢出。

### 壓畫面描邊寬（artStrokeRatio）
預設 0.16。值域 0–0.5。壓在畫面上的字的描邊寬，以字級的比例計（比對話框用的 0.10 粗一點，因為雜背景需要）。調低（往 0）：描邊太細、在畫面上讀不清。調高（往 0.5）：描邊吃進字、像貼紙。

### 直排每欄縮字（colTrim）
預設 3。值域 0–10。每個直欄少放幾個字。把欄縮短就會多出欄、字級自動縮小來塞。調低（0）：每欄塞滿、可能溢出框。調高：欄變很短、字級被逼很小。

### 橫排每行縮字（rowTrim）
預設 3。值域 0–10。直排縮字的橫排版——每行少放幾字，行變短、列變多、字級縮小。

### 字級整體縮放（fontScale）
預設 0.85。值域 0.3–1.5。排版挑好字級後再乘上的倍率。小於 1 讓字變小、在框內留邊距；預設留點呼吸空間。調低（往 0.5）：字普遍偏小、留白多。大於 1：字偏大、容易貼框或溢出。

## 效能（裝置相依）

這個只列到你 CPU 核心數為止。自動會依裝置調整，除非要跑 benchmark，否則選自動就對。

### OCR 並發度
下拉，預設自動（＝核心數）。OCR 同時辨識幾行，每行用一條緒。OCR 的圖塊小、吃不滿單次推論的多緒，所以用不同的行把核填滿比較快——一頁行數多時很明顯。搭配 int8 OCR 模型，整個 OCR 一頁約 0.25–1.8 秒跑完。超過核心數就沒核可填，所以選單停在那。

## 辨識（進階）

### 去字遮罩門檻（segThreshold）
預設 0.12。值域 0–1。偵測器逐像素的筆畫機率，超過此值才算「要去掉的字」。調低：算進來的像素變多，網點跟雜訊被拉進遮罩、去字伸進非文字。調高：只算最濃的筆畫，漢字旁的淡假名被留下成殘留。預設偏低就是為了抓那些淡假名。

### OCR 信心門檻（minProb）
預設 0.5。值域 0–1。一行 OCR 的平均信心低於此值就丟掉（不翻、不去字）。調低（往 0）：雜訊跟狀聲詞碎片被當文字翻成亂碼。調高（往 1）：風格化、戲劇性的字（偵測器常把它併成一個寬框、OCR 信心低）被丟掉、沒翻到。

### 跳過狀聲詞（ignoreSfx）
開關，預設關。跳過**翻譯**彩色/非氣泡的狀聲詞（SFX）——它們原樣留在畫面上、不會被去掉。有些人偏好保留裝飾性狀聲詞。這是「跳過翻譯」不是「積極去除」；引擎底層讀一個中段的 `ignoreBubble` 門檻，不對使用者暴露數字。
